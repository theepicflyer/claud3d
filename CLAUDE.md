# claude-3d

How Claude designs 3D-printed parts in this repo. The user describes a part. Claude writes a parametric build123d model, builds and checks it, and shows it to the user in a browser review app. Claude iterates on the user's comments and hands over a sliced file for the Bambu Lab X2D.

Read "How a project goes" before starting work; the sections after it are reference.

## Layout

```
CLAUDE.md             this file: how to work here
printer.toml          printer, slicer presets, design limits, fit clearances, materials
cadlib/               shared library and the `cad` CLI
  project.py          loads model.py and runs the build pipeline
  checks.py           printability checks
  render.py           offscreen PNG contact sheets
  topology.py         exact B-rep edges/faces per part, for the review app
  bambu.py            Bambu Studio presets, CLI slicing, opening projects
  features.py         FDM helpers: screw/nut tables, teardrop, nut trap, elephant-foot chamfer
  review/             browser review app (server, static files, vendored three.js r170) and comment store
  template/           copied by `cad new`
projects/<name>/
  CLAUDE.md           the project's requirements, interfaces, print notes, decisions, print log
  model.py            the parametric model
  review/             review threads and screenshots (committed)
  out/                build output (gitignored, regenerated by `cad build`)
tests/                pytest
```

## How a project goes

### 1. Pin down requirements

Before modeling, establish:

- what the part does
- what it mates with, with measured dimensions and how they were measured
- loads and environment: heat, outdoors/UV, flex, wear
- material, quantity, cosmetic faces, size or print-time limits

Ask in small batches. Write the answers into the project's CLAUDE.md as numbered requirements (R1, R2...), each with a measurable acceptance criterion. Call out ambiguity instead of guessing; when an assumption is unavoidable, record it under Decisions.

### 2. Set up the project

`uv run cad new <name>` (lowercase-kebab-case) creates `projects/<name>/` from the template. Work on a branch in a worktree (see Git).

### 3. Choose the print orientation

Decide it before modeling. Orientation sets layer-line strength, which faces need support, and which faces come out clean. Model every part in its print orientation, flat face down. Each part is dropped to z=0 automatically.

### 4. Model it

`model.py` defines:

```python
PARAMS = dict(...)                 # required; every dimension from a requirement or mating part; p.<name>
PRINT = dict(material="pla")       # optional: material, process, filament, machine, slicer={...}, design={...}, fit={...}
SECTIONS = {"part": ("y", 0.0)}    # optional: section plane per part or "assembly" for renders; default mid-Y
def build(p, s) -> dict[str, Part] # required; parts in print orientation
def assembly(p, s, parts) -> dict  # optional; parts moved to assembled positions
def features(p, s, parts)          # expected; named callouts for the user
def check(p, s, parts)             # expected; yield (ok, "R1 ...") per requirement
```

- `s` is `cadlib.config.Settings`. It provides `s.clearance(kind)`, `s.nozzle`, `s.layer_height`, `s.material`, `s.design[...]`, `s.nozzles`, `s.shared` and `s.build_volume`.
- Clearances always come from `s.clearance("press" | "snug" | "slide" | "loose")`, which includes the material's extra allowance. Never hardcode them.
- Follow the FDM design rules below.
- **`assembly()`** puts parts where they go when assembled. It drives the assembly render, the interference check, and the review app's assembled view.
- **`features()`** yields `dict(name, part, at, text, params=[...], normal=..., view=...)`.
  - The callouts show as labels, a list and a walkthrough in the review app. They teach the user the vocabulary for comments, and comments made near one are tagged with it.
  - Write one for each thing a user would talk about: walls, lips, holes, chamfers, clips, bosses. Name each in plain words and list the PARAMS that control it.
  - `at` is a point in the part's print frame, or a face/edge, whose center is used.
  - `normal` aims the walkthrough camera.
  - `view` is "print" or "assembly".
  - Keep the callouts current as the model changes.
- **`check()`** verifies each requirement by measuring the built geometry (bounding boxes, slices, distances). Echoing parameters back proves nothing.

### 5. Build and check your own work

`uv run cad build <name>` exports STEP/STL, runs the printability checks, renders PNGs, slices with Bambu Studio and writes `out/report.md`. It exits 1 on any FAIL.

1. Read `out/report.md` (see "Reading the report").
2. Look at every PNG in `out/` with the Read tool: proportions, features present and in the right place, nothing floating, sections showing the intended walls. The checks catch broken geometry; only looking catches design mistakes.
3. Iterate until the report is PASS, or every remaining WARN is understood and recorded under Decisions (for example, an intentional overhang that gets support).

### 6. Review with the user

1. Run `uv run cad review <name>` as a **background** Bash command and tell the user it's open. It serves on a fixed per-project port. A browser tab opens unless an existing tab reconnects within 4 s.
2. The user inspects the model, pins, circles and measures, writes comments, and presses "Send to Claude". The server then exits and prints the comments, which re-invokes Claude.
3. Each comment shows:
   - its id and part
   - the nearest feature callout
   - the anchor point and normal in the **part's print frame** (mm, after the drop to z=0, before plate placement)
   - the view it was made in
   - the build it was made against
   - a screenshot path
   Read every screenshot: it shows the user's viewpoint with the marker labelled "this". Map coordinates to features in `model.py` before changing anything, and ask when a comment is ambiguous.
4. Make the changes, rebuild, and record the reason under the project's Decisions. Answer each thread with `uv run cad reply <name> <id> "what changed" --resolve`; leave out `--resolve` to ask a question back. Then restart the review in the background. The user's tab reconnects, reloads the model and shows the replies.
5. `uv run cad comments <name> [--all]` lists threads, including ones sent while no session was running.

Comments and screenshots are stored in `projects/<name>/review/` and are committed with the project.

### 7. Hand off

Walk the user through the result: what changed, the report, slice time and filament, and any decision they haven't seen yet. `uv run cad open <name>` opens the sliced project in Bambu Studio (`--step` opens the STEP files in FreeCAD). Commit, open a PR and merge (see Git).

### 8. After printing

Record the result in the project's Print log. If fits come out consistently tight or loose across projects, adjust `[fit]` or the material's `clearance_extra` in printer.toml rather than patching individual models.


### Reading the report

- **manifold** FAIL: the solid is broken, usually from a bad boolean or a zero-thickness feature. Fix this first.
- **bodies** WARN: one part contains several disconnected solids. If that isn't intended, a feature didn't fuse; overlap booleans by 0.01 mm instead of using coincident faces.
- **build volume**: PASS if the part fits the region both nozzles reach. WARN if it fits only after a 90° turn about Z, or only on the left nozzle. FAIL if no nozzle can reach it. See "The X2D".
- **bed contact** WARN: little flat area on the bed. Consider a brim or reorienting.
- **overhangs** (red in renders): downward faces steeper than 45° from vertical. Fix by reorienting, chamfering instead of filleting, or using 45° transitions. An exact 45° chamfer passes.
- **bridges** (orange): flat downward faces.
  - `bridge`: supported on opposite sides; warns past 15 mm.
  - `cantilever`: a shelf supported on one side; warns past 2 mm.
  - `floating`: nothing below any edge; needs support.
- **wall thickness** (magenta dots): ray-cast thickness; warns below 1.2 mm, fails below 0.8 mm. Chamfer tips and sharp edges cause expected hits, so judge by the reported location.
- **interference**: overlap volume between assembled parts. Contact (gap 0.000) is normal for parts resting on each other.
- **spec**: the results of `check()`.
- **slice**: the Bambu Studio result, time, grams, and which nozzle the filament was mapped to. A slicer failure fails the build.

### Review app

- **Navigation is on the right mouse button:** drag pans, Ctrl+drag or middle-drag rotates, the wheel zooms. Shift+right-drag can't be used: Firefox-based browsers (Zen is installed here) always open their context menu on Shift+right-click.
- **The left button runs the current tool:** 1 pin, 2 circle, 3 measure. Esc cancels.
- **Measure:**
  - Snaps to exact B-rep vertices, circle centers, edge midpoints and edges. Ctrl+click places a point freely.
  - Shows distance, colour-coded ΔX/ΔY/ΔZ legs, "along X/Y/Z" when the distance is axis-aligned, face-to-face distance for parallel flat faces, and diameters.
- **Always shown:**
  - A readout panel with the hovered point's part-frame coordinates.
  - An axis triad.
- **Views:**
  - "Plate" layout: the parts on the X2D bed, with the right nozzle's unreachable strip shaded.
  - "Assembly" layout.
  - A section plane.
- **Data it reads:**
  - `out/view.json`: plate offsets, assembly transforms (a rigid fit between each part's printed and assembled tessellations), features, params and a report summary.
  - `out/<part>.stl` and `out/<part>.topo.json`.
- **Reloading:** an open tab reloads the model when `view.json` changes. It reloads itself, keeping the camera and unsent drafts, when files in `cadlib/review/static/` change.
- **`--keep`:** keeps serving after a send, for example while rebuilding repeatedly.
- **Testing UI changes:** run on a separate `--port` so tests don't touch the user's tab. Playwright saves screenshots only under the repo root (`.playwright-mcp/` is gitignored).

### FDM design rules (0.4 mm nozzle, 0.2 mm layers)

- **Walls:** at least 1.2 mm (3 lines); structural walls 2 mm or more. Floors and roofs at least 1.0 mm (5 layers). Prefer multiples of about 0.42 mm.
- **Strength:** parts are weakest across layer lines (Z). Orient so bending and tension run along the layers. Snap-fit arms and clips should flex in the XY plane.
- **Edges:**
  - Edges on the bed get a 0.4 mm chamfer against elephant foot (`F.elephant_foot_chamfer`).
  - Other downward-facing edges get a chamfer, not a fillet.
  - Fillets are fine on vertical and upward-facing edges.
- **Holes:** horizontal holes use `F.teardrop` (point up), or accept a slightly drooped top under about 6 mm. Vertical holes print 0.1-0.2 mm undersize; `F.SCREW_CLEARANCE` already allows for that.
- **Fasteners:**
  - Heat-set inserts for anything that gets reassembled (`bd_warehouse.fastener.InsertHole` / `HeatSetNut`, CNCKitchen sizes).
  - Otherwise nut traps (`F.hex_nut_trap`) or pilot holes for thread-forming screws (`F.PILOT_HOLE`).
  - Printed threads only at M8 and up or coarse custom pitches (`bd_warehouse.thread.IsoThread`).
- **Clearances:** diametral, PLA baseline, set in printer.toml: press 0.10, snug 0.20, slide 0.30, loose 0.50. Print-in-place gaps at least 0.3 mm per side.
- **Text:** at least 0.6 mm deep, 0.5 mm stroke and 6 mm tall. Put it on vertical faces or the top face, not on the bed face unless it's deliberately mirrored.
- **Bridges:** up to about 15 mm are fine; longer ones sag. Break long ceilings with ribs, or put the face on the bed.

### The X2D

The X2D has two nozzles with different reach. `config.py` reads the regions from the machine preset (`extruder_printable_area`, `extruder_printable_height`) at build time. Bed coordinates have their origin at the front-left corner.

| Nozzle | Drive | X | Y | Max Z | Volume |
|---|---|---|---|---|---|
| Left (main, extruder 1) | direct drive | 0-256 | 0-256 | 261 | 256 x 256 x 261 |
| Right (auxiliary, extruder 2) | Bowden | 20.5-256 | 0-256 | 256 | 235.5 x 256 x 256 |

- **Right nozzle's reach:** it can't reach the leftmost 20.5 mm strip of the bed or the top 5 mm. Bambu's spec sheet lists the main nozzle at 260 mm; the slicer preset allows 261.
- **Multi-material:** multi-material prints, and anything that might print on the right nozzle, must stay within the shared 235.5 x 256 x 256 region. Only single-material prints on the left nozzle get the full volume.
- **Long parts:** both nozzles cover the full 256 mm in Y. A part longer than 235.5 mm in one direction usually fits both once its long side runs along Y. Do that unless the orientation matters.
- **Plate layout:** `cad build` lays parts out on the plate itself (shelf packing, 5 mm gaps), inside the shared region when everything fits. The slicer's own auto-arrange only uses the shared region and rejects larger parts, so it is turned off.
- **Nozzle choice:** the CLI maps a single filament to the left nozzle. When printing from the GUI with the AMS, the nozzle is chosen at print time.

### Materials

On hand: PLA (the default), PETG, ABS-GF, and TPU 95A, which hasn't been tried on this printer yet. printer.toml `[materials]` holds each one's slicer preset, extra clearance and notes.

- **PLA:** indoor parts and prototypes.
- **PETG:** toughness, heat up to about 70 °C, outdoor use.
- **ABS-GF:** stiff parts that see heat (about 95 °C) or need dimensional stability. Round the vertical corners of large flat bottoms against warping.
- **TPU:** flexible parts. Left nozzle only, walls at least 1.6 mm, no supports or long bridges.

### build123d

- **Units and style:** units are mm. Prefer algebra mode (`part = Box(...) - Pos(...) * Cylinder(...)`); builder mode is fine for sketch-heavy work.
- **Planes:** `Plane.XZ`'s normal points -Y. When direction matters, build `Plane(origin=..., z_dir=...)` explicitly.
- **Selecting:** select with `.edges().filter_by(Axis.Z)`, `.group_by(Axis.Z)[-1]`, `.sort_by(...)` or `face.outer_wire().edges()`. The edges of rounded profiles are several line and arc segments.
- **Fillets and chamfers:** apply them last. If one fails, reduce its size or select fewer edges. Small radii next to tight corners fail first.
- **Catalog parts:** bd_warehouse has fasteners, threads, bearings, gears and pipes. Prefer it over hand-rolling catalog parts.

### Environment

- Python goes through uv only (`uv run`, `uv add`), pinned to 3.13.
- Bambu Studio is the flatpak `com.bambulab.BambuStudio`.
  - Its CLI needs flattened presets, so `bambu.py` resolves the `inherits` chains from the system profiles and from the user's presets in `~/.var/app/com.bambulab.BambuStudio/config/BambuStudio/user/`. The default machine preset is the user's `My X2D 0.4 nozzle`.
  - The flatpak only sees `$HOME`, so files given to the slicer must live under it, not in `/tmp`. Tests use `.tmp-test/` (gitignored).
  - Headless slicing logs a GLFW/OpenGL error. It only affects plate thumbnails.

### Git

- **The repo:** one repo for the whole folder, on GitHub as `theepicflyer/claude-3d` (private).
- **Ownership:** Claude owns git here. It branches, opens PRs and merges without asking, once tests pass and the work has been walked through with the user.
- **Workflow:**
  - Work on one branch per project or tooling change, in a worktree under `.worktrees/` (gitignored), and run `uv sync` in a new worktree.
  - Use merge commits; no force pushes.
  - Review comments written in the main checkout belong to the project's branch. Move them into the worktree before committing.
- **Docs:** keep this file a coherent how-to-work document. When behavior changes, edit the section where it belongs instead of appending notes. Keep README.md and each project's CLAUDE.md current too.
